Factory Inventory Management System

Architecture overview — a Vue 3 single-page frontend backed by a FastAPI service that filters in-memory data loaded from JSON fixtures at startup. No database, no auth, no persistence beyond process lifetime.

Overview Tech Stack Architecture Data Flow API Reference Project Structure Notes & Gaps

Overview

What it is

  • Demo factory inventory dashboard: stock levels, orders, demand forecasts, backlog, and spending.
  • Two processes: a Vite dev server (frontend) and a Uvicorn/FastAPI process (backend).
  • All data lives in JSON files, loaded into memory once at backend startup.

How it runs

  • Frontend on localhost:3000, backend on localhost:8001.
  • Frontend calls the backend directly over HTTP via axios — no reverse proxy.
  • CORS is wide open (allow_origins=["*"]) — dev-only posture.

What it's not

  • No database — a server restart discards nothing (it re-reads JSON), but nothing written is ever persisted either.
  • No authentication, no rate limiting, no CI, no Dockerfile.
  • Not production-ready by design — it's a demo/prototype.

Data Flow — worked example

Tracing a warehouse filter change on the Inventory page, end to end, citing the actual files and functions involved.

  1. User picks a warehouse in FilterBar.vue's <select v-model="selectedLocation">. That ref comes from useFilters() — a singleton composable, so the mutation is instantly visible to every other component that imported it.
  2. Inventory.vue also calls useFilters() and has watch([selectedLocation, selectedCategory], () => loadInventory()) — inventory has no time dimension, so it only watches location/category, not period or status.
  3. loadInventory() reads getCurrentFilters() and calls api.getInventory({ warehouse, category }).
  4. api.js builds a URLSearchParams, omitting any filter equal to 'all', and does axios.get('http://localhost:8001/api/inventory?warehouse=...').
  5. FastAPI's get_inventory(warehouse, category) handler calls apply_filters(inventory_items, warehouse, category), a plain list comprehension over the in-memory inventory_items list that mock_data.py loaded from inventory.json at process startup.
  6. The filtered dicts are returned with response_model=List[InventoryItem] — FastAPI/Pydantic coerces and validates every item before serializing the JSON response.
  7. Back in Inventory.vue, the response is assigned to a raw ref (items); a computed re-derives the sorted, searched, stock-status-annotated list that the table template renders.

Dashboard.vue follows the same shape but wider — loadData() fires four calls in parallel (Promise.all: summary, orders, inventory, backlog), populating raw refs (allOrders, inventoryItems), with computed properties (statusData, categoryData, revenueGoal) deriving everything the page displays.

Notes & Gaps

GAP Frontend calls endpoints the backend doesn't have api.js defines getTasks, createTask, deleteTask, toggleTask (/api/tasks*) and createPurchaseOrder, getPurchaseOrderByBacklogItem (/api/purchase-orders*). None of these routes exist in main.py — they would 404. Task loading fails silently (the caller catches and logs); purchase-order creation from the backlog UI would surface an error. The Pydantic models PurchaseOrder and CreatePurchaseOrderRequest exist but are never wired to a route.
DEV-ONLY No production hardening CORS allows every origin, there's no authentication, no rate limiting, no database, no Dockerfile, and no CI workflow. All of this is intentional for a local demo — see the root and server/ CLAUDE.md files — but any of it would need addressing before deployment.
BY DESIGN Restart-to-reload data model All fixtures load once into module-level lists when mock_data.py is imported. Editing a JSON file under server/data/ has no effect until the backend process restarts.
